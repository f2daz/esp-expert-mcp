# ESP8266 – specifics

The ESP8266 differs fundamentally from the ESP32 family. Do not transfer ESP32 knowledge (FreeRTOS tasks, two cores, plenty of RAM, ADC calibration). Chip data via `chip_info`, pins via `pin_check`.

## Architecture and execution model

- **Single core**, Tensilica **LX106**, 80/160 MHz. No Bluetooth. External SPI flash (except ESP8285).
- **Arduino core: no FreeRTOS.** The sketch runs cooperatively together with the SDK's Wi-Fi/TCP stack. Code that does not yield blocks the network.
- Yielding to the system: end of `loop()`, `delay(ms)`, `yield()` (= `delay(0)`).
- The **software watchdog** (message `Soft WDT reset`, with stack trace) and the hardware watchdog (reset without stack trace) trigger when blocking too long.
- Guideline values from the core docs: `loop()` iterations without `delay()` longer than about 50 ms endanger Wi-Fi stability; `delayMicroseconds()` does not yield – do not exceed about 20 ms.
- **Stack only about 4 KB** (Arduino core) – no large local buffers/objects.

```cpp
// Wrong: blocks, soft WDT
while (!sensorReady()) {}

// Right: time-limited and with yield()
const uint32_t t0 = millis();
while (!sensorReady()) {
  if (millis() - t0 > 500) { handleTimeout(); break; }
  yield();
}
```

- Program non-blocking: state machines with `millis()`, `Ticker` for periodic tasks (keep the callback short, only set a flag).
- **Callbacks** from Wi-Fi events, `Ticker`, async libraries (ESPAsyncTCP/-WebServer) run in SYS context: no `delay()`, `yield()`, no long operations, no blocking network calls there. Set a flag, do the work in `loop()`.

## ISR

- Mark ISRs with **`IRAM_ATTR`** (otherwise a crash on `attachInterrupt`, because the flash cache may be busy). `ICACHE_RAM_ATTR` is the older spelling (deprecated in newer cores, verify) – use `IRAM_ATTR` in new code.
- Forbidden in an ISR: `delay()`, `yield()`, `malloc`/`free`/`new`/`delete`, `String`, `std::vector`, `Serial.print`.
- Keep ISRs short (run times > 1 ms disturb Wi-Fi/TCP). Make shared variables `volatile`, briefly protect multi-byte accesses in `loop()` with `noInterrupts()`/`interrupts()`.
- **GPIO16 cannot do interrupts.**

```cpp
volatile uint32_t pulses = 0;
void IRAM_ATTR onPulse() { pulses++; }

void setup() {
  pinMode(D5, INPUT_PULLUP);                    // D5 = GPIO14
  attachInterrupt(digitalPinToInterrupt(D5), onPulse, FALLING);
}
```

## Memory: heap, fragmentation, flash strings

- The heap is small (typically a few tens of KB free after Wi-Fi start; measure with `ESP.getFreeHeap()`, do not estimate). **According to the core docs, out-of-memory is the most common cause of crashes.**
- Diagnostics: `ESP.getFreeHeap()`, `ESP.getMaxFreeBlockSize()` (largest contiguous block), `ESP.getHeapFragmentation()` (0 % clean, > ~50 % critical).
- Avoid fragmentation:
  - No repeated `String` concatenation in `loop()`; if `String`, then `reserve()`; better fixed `char` buffers + `snprintf`.
  - Allocate buffers once and reuse them; no `new`/`delete` on every cycle.
  - TLS (BearSSL) needs a lot of RAM – reduce buffer sizes (`setBufferSizes`) if the server supports MFLN.
- Constant strings into flash:
  ```cpp
  Serial.println(F("Start"));                      // string literal in flash
  static const char HTML[] PROGMEM = "<html>...</html>";
  server.send_P(200, "text/html", HTML);           // _P variants read from PROGMEM
  char c = pgm_read_byte(HTML + i);                // manual access
  ```
  `pgm_read_byte/word/dword/float/ptr` for PROGMEM data; flash data is only readable aligned (4 bytes) – direct byte accesses to PROGMEM without `pgm_read_*` can trigger exception 3.
- Cache/IRAM memory split via the board option `mmu` (e.g. `3232` balanced, `4816` more IRAM).

## Pins and boot

| GPIO | Notes |
|---|---|
| 0 | Strapping: LOW at boot = UART download. External pull-up; button to GND is fine |
| 2 | Strapping: must be HIGH at boot; often the onboard LED |
| 15 | Strapping: must be LOW at boot (pull-down on modules) |
| 1, 3 | UART0 TX/RX (Serial, flashing) |
| 6–11 | **Flash SPI – do not use** (crash). ESP8285: GPIO9/10 usable depending on module |
| 16 | No interrupt, no PWM/I2C usually; `INPUT_PULLDOWN_16`; connect to RST for deep sleep wake |
| A0 | Only ADC, 10 bits, **0–1.0 V at the chip** (boards with divider: D1 mini/NodeMCU about 0–3.2/3.3 V – check the board) |

Boot modes: **Flash boot** GPIO15=0, GPIO0=1, GPIO2=1; **UART download** GPIO15=0, GPIO0=0, GPIO2=1.

- Choose external circuitry on GPIO0/2/15 so that the boot levels are not violated (e.g. no load that pulls GPIO2 LOW during reset).
- ADC: `analogRead(A0)` returns 0–1023. With `ADC_MODE(ADC_VCC);` (global), A0 measures the supply voltage instead (`ESP.getVcc()`); leave A0 unconnected then. While Wi-Fi is active, `analogRead()` is throttled.
- PWM (`analogWrite`) is software PWM: default range 0–255 from core 3.0 (previously 0–1023), default 1 kHz, `analogWriteFreq()`/`analogWriteRange()`.
- 3.3 V logic levels, not 5 V tolerant (not stated in the datasheet – do not rely on it).

## Deep sleep

```cpp
ESP.deepSleep(60e6);           // µs; wakes only if GPIO16 is connected to RST
// max. duration: ESP.deepSleepMax()
```
- After waking, the chip restarts (`setup()` from the beginning); keep state in RTC memory (`ESP.rtcUserMemoryWrite/Read`) or flash.
- Modes: `WAKE_RF_DEFAULT`, `WAKE_RFCAL`, `WAKE_NO_RFCAL`, `WAKE_RF_DISABLED`.
- The GPIO16–RST connection can interfere with flashing via auto-reset → make it detachable via jumper/resistor if needed (verify per board).
- Reset reason: `ESP.getResetReason()`.

## ESP8285

- ESP8266 with **1 MB integrated flash** (DOUT); as a result, GPIO9/10 are free depending on the module.
- 1 MB is only enough for OTA with a small sketch and a small or no filesystem.

## Flash layout and filesystem

```
| Sketch | OTA area | Filesystem | EEPROM | Wi-Fi config (SDK) |
```
- The layout is selected via the board option `eesz` (e.g. `4M2M` = 4 MB, 2 MB FS; `4M` = without FS). PlatformIO: `board_build.ldscript = eagle.flash.4m2m.ld`.
- **LittleFS instead of SPIFFS**: SPIFFS is deprecated in the core and may be dropped. `#include <LittleFS.h>`, `LittleFS.begin()`. Different formats – switching means reformatting.
- Flashing a new sketch does not change the filesystem; `erase`/"Erase Flash: All Flash Contents" does.
- The configured flash size must not be smaller/larger than the real one (symptom: FS mount errors, OTA fails).

## OTA

- The flash must hold **old and new firmware at the same time**: the new firmware is stored between sketch and filesystem, then eboot copies it on restart. Rule of thumb: **sketch ≤ half of the free area** (sketch + OTA area).
- Check before the update: `ESP.getFreeSketchSpace()` ≥ size of the new firmware.
- ESP-01 with 512 KB: practically no OTA. A large FS reduces the OTA space.
- Secure ArduinoOTA with a password; `ESP8266HTTPUpdate` for pull updates (mind the TLS RAM requirements).

## Exceptions and crash analysis

- Copy the crash output between `--------------- CUT HERE FOR EXCEPTION DECODER ---------------` and decode it with **the ELF of the currently flashed sketch**:
  `serial_log_analyze`, PlatformIO filter `esp8266_exception_decoder` or EspExceptionDecoder (Arduino IDE).
- Exception codes (EXCCAUSE): `0` illegal instruction, `2`/`3` address/data error on instruction fetch or load/store (e.g. byte access to flash/PROGMEM without `pgm_read_*`, ISR without `IRAM_ATTR`), `6` division by zero, `9` unaligned access, `28`/`29` prohibited read/write access (typically a null pointer or freed memory).
- `Soft WDT reset` → blocking code without `yield()`; `wdt reset` without a stack → hardware WDT (often a blocked ISR or a disabled soft WDT).
- `rst cause`/`boot mode` in the ROM output (74880 baud) show the reset reason and boot mode – set the monitor to 74880 for this.

## ESP8266_RTOS_SDK

- Espressif's FreeRTOS-based SDK in IDF style. According to the announcement in the repo (issue #1166), **no new major versions and no new features**; components are only updated as needed (verify). Support policy: 18 months per minor release, LTS 30 months; V3.2 and older are EOL, check the status of V3.3+/V3.4 in the policy or release branches.
- Not recommended for new projects; keep existing projects on a maintained release branch.
- The Arduino core and ESPHome are not based on it (the Arduino core uses a NONOS SDK base).

## When the ESP8266 still makes sense today

- Existing devices (Sonoff, Shelly Gen1, D1 mini builds), maintenance of existing firmware, simple ESPHome/Tasmota sensors.
- Very cost-critical, simple Wi-Fi sensors without TLS-heavy communication.
- **New development:** better ESP32-C3/C6 (RISC-V, FreeRTOS, BLE, more RAM, actively maintained ESP-IDF, Secure Boot/flash encryption) – check pin and form-factor compatibility with `chip_info`/`pin_check`.
